# 03 - Relational SQL

This section confirms normal relational database usage through Database Actions.

I created a small activity table, inserted the lab milestones, committed the rows, and queried the completed data.

## Table design

`LAB_ACTIVITY_LOG` contains:

| Column | Purpose |
| --- | --- |
| ACTIVITY_ID | Identity-based primary key |
| ACTIVITY_NAME | Description of the lab activity |
| STATUS | Current activity status |
| CREATED_ON | Timestamp generated by the database |

## Why this table exists

The table is intentionally simple. The point is to prove a complete relational workflow before moving to vector operations:

```text
CREATE TABLE
     |
INSERT
     |
COMMIT
     |
SELECT
     |
UPDATE
     |
VALIDATE
```

The final validation showed all four lab activities as **COMPLETED**.
